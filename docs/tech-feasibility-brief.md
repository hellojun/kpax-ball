# KPAX Ball 保险 + 杠杆 技术可行性说明

---

## 产品概述

KPAX Ball 是一个 Polymarket 足球盘口分析工具（Chrome 插件）。在现有 AI 分析能力基础上，计划新增两个金融功能：

- **保险**：用户在 Polymarket 下注后，可以向 KPAX 买一份保险。输了能拿回部分本金。
- **杠杆**：用户出一部分钱，KPAX 借钱给他，放大收益（也放大风险）。

---

## 一、保险

### 它是什么

保险的本质是**对赌**。用户在 Polymarket 买了"曼城赢"，然后花 $22 向 KPAX 买保险。如果曼城真的输了，KPAX 赔用户 $70。如果曼城赢了，这 $22 就是 KPAX 的利润。

KPAX 不需要去 Polymarket 下单，也不需要监控用户的持仓。这就是一个独立的对赌产品，用 KPAX 自己的 AI 分析能力来定价。

### 中心化方案

用户充值 USDC 到 KPAX 平台，KPAX 记录一笔余额。买保险时扣余额，赔付时加余额。所有资金记录在 KPAX 的数据库里。

```
用户充值 → KPAX 钱包收到 USDC → 数据库余额 +$100
买保险 → 数据库余额 -$22，创建保单
比赛结束：
  用户赢了 → 保单作废，KPAX 赚 $22
  用户输了 → 数据库余额 +$70，KPAX 亏 $48
用户提现 → KPAX 从钱包转 USDC 给用户
```

**优点**：开发快（2-3 周），用户体验简单
**缺点**：用户要信任 KPAX 不跑路。KPAX 持有所有资金。

### 去中心化方案

部署一个智能合约（保险池），用户的保费和赔付都通过合约自动执行。KPAX 只往池子里注入启动资金，不能随意提走。

```
KPAX 注入 $10,000 到保险池合约
用户买保险 → $22 转入合约 → 合约记录保单
比赛结束 → 链上预言机喂入结果：
  用户赢了 → 合约标记保单过期
  用户输了 → 合约自动转 $70 给用户
KPAX 只能提走利润部分，不能提走用于赔付的保障金
```

**优点**：资金透明，链上可验证，用户不需要信任 KPAX
**缺点**：需要开发和审计智能合约（8-10 周），需要预言机喂入比赛结果

## 二、杠杆

### 它是什么

用户出 $100，KPAX 借给他 $200，总共 $300 买入 Polymarket 的份额。如果赢了，收益翻 3 倍。如果亏损超过保证金，KPAX 强制卖出（平仓）保护自己的借款。

核心难点：**KPAX 必须能强制卖掉用户的持仓**。这意味着持仓 token 不能在用户自己的钱包里，必须在 KPAX 能控制的地方。

### 中心化方案

KPAX 用自己控制的钱包在 Polymarket 代替用户下单。用户在 KPAX 看到一个"仓位"，但实际的 token 在 KPAX 的钱包里。

```
用户保证金 $100 → 从 KPAX 余额扣除
KPAX 出资 $200 → 系统钱包总共 $300
KPAX 用系统钱包在 Polymarket 买入 $300 的 token
  → token 在 KPAX 控制的钱包里
  → 用户只在 KPAX 界面看到仓位信息

后台每分钟检查价格：
  价格跌到强平线 → KPAX 直接用系统钱包卖出 token
  → 卖出所得先还 $200 借款 → 剩余还给用户余额

比赛结束：
  赢了 → 收益 $300，还 KPAX $200 + 利息，用户拿剩余
  输了 → 收益 $0，用户保证金全损（但 KPAX 应该在之前已经强平了）
```

**优点**：实现简单（3-4 周），KPAX 完全可控
**缺点**：用户的钱和持仓都在 KPAX 手里，信任风险最高

### 去中心化方案

部署一个智能合约（杠杆保险柜）。用户的保证金和 KPAX 的借款都锁在合约里，合约自动在 Polymarket 买入 token。token 锁在合约中，双方都不能单独转走。

```
用户 $100 → 转入杠杆合约
KPAX $200 → 转入杠杆合约
合约自动在 Polymarket 买入 $300 的 token
  → token 锁在合约里，谁都不能直接转走

合约内置清算规则：
  if (持仓价值 < 借款 × 1.2) → 任何人都可以触发清算
  KPAX 的 keeper 机器人负责监控并触发
  → 合约自动卖出 token → 先还 KPAX 借款 → 剩余给用户

比赛结束：
  合约读取预言机的比赛结果 → 自动分配资金
```

**优点**：
- 用户资金在合约中，KPAX 无法挪用
- 清算规则写死在代码里，不可篡改
- 所有操作链上可审计
- 未来可以让外部投资者（LP）注入借贷资金，扩大资金池

**缺点**：
- 合约开发复杂（8-12 周）
- 必须做安全审计（2-4 周，费用 $20K-$50K）
- 链上操作有 gas 成本
- 需要可靠的价格预言机

## 三、用户体验对比

### 中心化

```
用户视角：
1. Google 登录 KPAX 插件
2. 看到充值地址，转入 USDC
3. 余额到账，一键买保险 / 开杠杆
4. 赛后自动结算，余额变化
5. 随时提现

感受：像用一个 App，简单快速
担心：钱在别人手里
```

### 去中心化

```
用户视角：
1. Google 登录 KPAX 插件（自动创建链上智能账户）
2. 转入 USDC 到自己的智能账户
3. 点击买保险 → 链上交易确认（等几秒）
4. 赛后合约自动赔付到账户
5. 随时提现到任意钱包

感受：多等几秒确认，但钱始终在自己的链上账户里
信任：不需要信任 KPAX，信任代码就行
```

## 四、总结

|  | 保险 | 杠杆 |
|--|------|------|
| **技术难度** | 低（对赌账本） | 高（需要控制持仓） |
| **中心化开发周期** | 2-3 周 | 3-4 周 |
| **去中心化开发周期** | 8-10 周 | 12-16 周（含审计） |
| **资金需求** | KPAX 需要保险资金池 | KPAX 需要借贷资金池 |
| **核心风险** | KPAX 连续赔付导致资金池耗尽 | 极端行情下强平不及时，KPAX 借款损失 |

### 推荐路径

| 阶段 | 做什么 | 时间 |
|------|--------|------|
| **第一步** | 中心化保险上线 | 3 周 |
| **第二步** | 中心化杠杆上线 | 4 周 |
| **第三步** | 去中心化合约开发 + 审计 | 12-16 周 |
| **第四步** | 迁移到去中心化 | 4 周 |

先用中心化方案快速验证需求，同步开发去中心化合约，最终迁移过去。
